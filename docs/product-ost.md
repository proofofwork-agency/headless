# Product Opportunity Solution Tree

Living map for Headless product improvement (Teresa Torres OST style). Update when Loop scores change.

## Outcome

Operators choose Headless for **safe heterogeneous servants** and complete **first value** (contained run + verify path) fast enough that they do not bounce to Conductor / native multi-agent for basic use.

```text
OUTCOME: TTFV ≤ 5m + trustworthy first receipt path + thin stable surface
│
├── O1 Reduce onboarding ceremony (W1, W2)
│   ├── S1 headless setup wizard
│   ├── S2 --profile read-only-native | broker-readonly
│   └── S3 one-path README + quickstart
│
├── O2 Progressive disclosure (W2, W5, W3)
│   ├── S4 STABLE_COMMAND_NAMES + experimental namespace (exists; keep enforced)
│   ├── S5 CLI remedy matrix
│   └── S6 TUI next-action + authority ladder
│
├── O3 Ship & focus (W3, W4)
│   ├── S7 freeze new stable commands (AGENTS.md)
│   ├── S8 product-gate automation
│   └── S9 human publish decision (out of band)
│
├── O4 Multi-agent trust UX (W6)
│   └── S10 Overview health + next actions for trust/login/first exec
│
└── O5 Sustain (W7; defer W8/W9/W10)
    └── S11 god-module splits only when velocity requires
```

## Active loop

**Loop 1–3 execution:** implement S1–S8 and S10; re-gate via `bun scripts/product-gate.ts` and tests until automated Product Gate checks pass.

## Non-goals

Windows (W8), enterprise procurement (W9), matching same-vendor subagent depth (W10), Conductor visual parity, weakening required containment.
