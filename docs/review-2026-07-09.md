# Headless — Project Review, Rating, and Improvement Roadmap

Date: 2026-07-09. Method: four independent analysis streams — (1) full repo audit, (2) ContextRelay reference map (`../agenttalk/contextrelay`), (3) OpenCode plugin-API ground truth from the vendored clone (`opencode/`, anomalyco/opencode v1.17.17 @ 08096b5) plus a web ecosystem scan, and (4) an independent implementer's assessment by Codex via ContextRelay — reconciled by Claude (coordinator). Verified at review time: `bun run check` green (33 tests / 111 expects), `bun run build` green.

## Executive summary

Headless is a **credible, honestly-scoped MVP with a genuinely strong runtime spine** — the hash-chained ledger is ahead of even ContextRelay (the mature reference) on tamper-evidence — but its **most load-bearing safety claim (contained read-only execution) was the least backed by code** at review time, its OpenCode plugin could not actually be loaded by OpenCode as sited, and the package was not publishable. None of these are architectural flaws; all are addressable in small slices, and the reference implementations for the hard parts (worktree isolation, OS sandbox, env allowlisting, redaction) already exist in ContextRelay with near-zero external dependencies.

**Overall: 5.5/10 as reviewed — clearly a prototype, but one with an unusually solid core and a clear path to 8/10.**

## Key findings (ranked)

1. **[CRITICAL] Read-only is not contained for opencode.** `assertModeAllowed` only rejects `mode:"write"` on non-canWrite backends; a "read-only" opencode run gets the full-access default agent and full `process.env`. The containment recipe (OPENCODE_CONFIG_CONTENT tool/permission denies + env scrubbing + macOS sandbox) is described in this repo's own `docs/analysis-opencode.md` but was never ported. → Slice 1 (in progress).
2. **[HIGH] Plugin cannot load where it sits.** No `.opencode/plugin/` placement, no `opencode.json` `"plugin"` entry; npm path structurally broken. Fix is cheap; tool definitions themselves need no changes. → Slice 2.
3. **[HIGH] Publishability broken**; LICENSE was missing; no CI; no git history (fixed: baseline `6ebb939`). → Slice 5.
4. **[MED] Correctness batch:** silent `--model`/`--agent` drop (claude/codex); ledger unsigned-tail acceptance; `collectText` double-emit of string `content`; opencode parser dual-path double-collect; CLI arg foot-guns (`--model --json`, last-positional prompt, stack trace on bad backend); `deliberate` marks its handoff handled even when all workers fail; token overcounting (`total_tokens` summed with subsets). → Slice 3.
5. **[MED] O(n²) ledger appends** — full read+verify+rewrite per event; fine at MVP scale, degrades on long sessions.
6. **[LOW] Buffered-only output** — no live streaming; ContextRelay's `readline` line-reader idiom is the port target.

## Competitive positioning (ecosystem scan, mid-2026)

The OpenCode plugin ecosystem is mature and crowded (~150+ plugins; official ecosystem page + awesome-opencode). Multi-agent orchestration plugins already exist and are prominent: oh-my-openagent (OMO), OpenCode Ensemble, Mission Control, opencode-orchestrator, Open Conclave — most use git-worktree isolation and a shared task board, but **orchestrate OpenCode-only sub-agents**. Headless's defensible wedge is exactly its two non-negotiables:

- **Cross-backend execution** — one normalized runner over opencode / claude-code / codex / grok, which no prominent incumbent offers;
- **Tamper-evident native ledger** — hash-chained, verified-on-read audit trail; incumbents have dashboards, not auditability.

Conclusion: don't compete on orchestration UI; compete on *safe, auditable heterogeneous execution* — the "boring infrastructure" the orchestrators above could themselves build on.

## Reference assets (ContextRelay, ready to port)

All porting-relevant modules use only Node/Bun builtins. Ephemeral write-worktrees (`src/session/worktree.ts` + `git-helpers.ts`, fail-closed, diff capture, orphan sweep); macOS Seatbelt sandbox (`src/backup/os-sandbox.ts`, 148 LOC, probe-gated, self-contained); contained spawn + env credential allowlist (`src/backup/runner.ts`); opencode-as-worker deny recipe (`src/backup/opencode-adapter.ts`); redaction (`src/session/redaction.ts`, 41 LOC drop-in, 13 secret patterns); usage-control profiles; concurrency pool; kill-tree; SessionLock. Notably, ContextRelay's ledger has **no** hash chain — headless should keep its own chain and port redaction/compaction on top, not replace it.

## Remediation completed (2026-07-09 evening — Claude coordinator + Codex implementer)

All six planned slices landed and merged to `main` in one session (Codex implemented under ContextRelay handoffs; Claude designed, reviewed, and committed; git history is now real). Test suite grew 28 → **67 tests / 309 expects**, `bun run check` and `bun run build` green throughout.

What materially changed versus the scorecard above:

- **Containment 3 → ~7.** The critical read-only hole is closed: opencode runs inject `OPENCODE_CONFIG_CONTENT` tool+permission denies (verified against vendored v1.17.17 that env config merges late as local config), and all backends spawn with a credential-allowlisted child env instead of the full parent environment. **Verified live**: an A/B test in the real opencode binary showed the deny config actually blocks the bash tool (control run wrote a file; treatment run with denies wrote nothing).
- **Write mode is now genuinely contained.** `--mode write` runs in an ephemeral git worktree, captures a diff-only ledger artifact, and never mutates the caller's tree (git-required, fail-closed on non-git/dirty-primary, force-cleanup, orphan sweep). Verified end-to-end with a real grok-build run: worktree created, diff captured even on backend failure, primary untouched, zero orphans.
- **Plugin loadability 5 → ~8.** `opencode.json` file-spec entry makes the plugin discoverable; identity/scope fixed; a no-mock loader-contract test runs against the real `@opencode-ai/plugin` (pinned 1.17.17).
- **Auditability 7 → ~8.** Ledger unsigned-tail bypass closed; append/read seq accounting made consistent; **redaction-on-write** now strips 13 secret-pattern classes before hashing (the authorized live caller still sees raw output; only the durable ledger is sanitized).
- **Backends 6 → ~7.** claude/codex `--model` passthrough fixed; parser double-emit and token overcount fixed; CLI foot-guns replaced with friendly errors.
- **Packaging 2 → ~7.** Real git repo; LICENSE; `npm pack` now ships working `dist/` (JS + `.d.ts`) with a `files` allowlist and `prepublishOnly` build. (Not yet pushed to a remote; no CI until there is one.)

**Revised overall: ~5.5 → ~7.5/10.** The MVP's load-bearing safety claim is now backed by code and verified in the real binaries; remaining gaps are the BACKLOG row (streaming, O(n²) compaction, OS sandbox, MAC signing, Linux containment) rather than correctness or false-safety holes.

## Live end-to-end validation (2026-07-09 evening, real binaries)

Beyond the test suite, the load-bearing claims were exercised against the actual CLIs and produced one real bug fix:

- **opencode read-only containment** — A/B in the real opencode binary: control run wrote a file via the bash tool; the run with injected `OPENCODE_CONFIG_CONTENT` denies wrote nothing (bash blocked at the permission layer).
- **Contained write mode** — real grok-build run created the ephemeral worktree, executed in it, captured a diff even when the backend failed, left the primary tree untouched, and cleaned up with zero orphan worktrees/branches.
- **Cross-backend dogfood + ledger audit** — fanned a read-only task across opencode+claude+codex through `deliberate()`; the ledger/hash-chain/read-model/task-state pipeline verified flawless (all backend failures captured cleanly, no crash). **This surfaced a real bug**: the codex backend burned ~23k tokens and returned no output because `parseCodexJson` didn't match codex 0.143.0's `item.completed`/`agent_message` envelope. Fixed with a live-captured golden fixture (commit `8048c78`); codex now returns correct output (`ARTICHOKE 4`).
- **Plugin load in real opencode** — ran opencode in-repo; it discovered and loaded the plugin, invoked `headless_task_state`, and the tool wrote a ledger under opencode's real session id — confirming the `ToolContext` wiring, not just the type contract.
- **Backend status:** opencode ✓ (needs an explicit `--model` in `--pure` mode), codex ✓, and claude ✓ validated live (claude's headless auth needed `USER`/`LOGNAME` in the env allowlist — Keychain access — fixed in `a33288c`); **grok-build** needs an account balance — user-side, not code.

## Post-review additions (2026-07-10)

- **Pushed to a private remote** — `github.com/proofofwork-agency/headless`, and **CI** runs `bun install --frozen-lockfile` + check + build on every push/PR (green; proves the suite is portable, not macOS-only).
- **OS sandbox landed** (macOS Seatbelt, auto-detected; `6f…`-series → merged). Read-only runs on macOS get an OS-enforced floor beneath the app-level denies. Design note: the initial allow-list port broke real backends live (opencode `SQLITE_AUTH`, claude Keychain "Not logged in"), so it was pivoted to a **deny-list** — allow the backend to run, deny writes to the project dir + credential dirs + interactive shells. Live-verified: claude returns correct output and opencode runs to completion under the sandbox while cwd writes are denied. codex is exempt (self-sandboxes); write mode keeps worktree containment. Non-macOS/probe-fail falls back to app-level containment.
- **Containment now spans all three layers on macOS**: per-backend app denies (all platforms) + ephemeral worktrees for write mode + OS Seatbelt for read-only. The remaining containment gap is **Linux** (bubblewrap/landlock — no reference port yet).
- **Adversarial hardening pass** (3-agent review → fixes, all tested; see `SECURITY.md`). Closed real bugs the earlier build missed: two opencode read-only bypasses (`OPENCODE_PERMISSION` env override; prompt→flag smuggling), CLI flag-vs-`--` isolation, a ledger **all-unchained forgery bypass** (verification could be skipped entirely), redaction that only covered `content` (secrets in artifact/handoff/meta leaked), sandbox probe-failure latching, and parser/stdout/process-tree DoS. Added an optional **HMAC ledger** (`HEADLESS_LEDGER_KEY`) for tamper-*proof* integrity. Accepted limits (write-mode OS backstop, macOS-only sandbox, allow-default profile ceiling, HMAC key custody, etc.) are documented in `SECURITY.md`.

**Revised overall after hardening: ~8.5/10.** The containment and audit core — the whole thesis — has now survived an adversarial review with its real holes closed and its ceilings honestly documented.
